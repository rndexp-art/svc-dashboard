Wired in Phase 4.

The "create project" flow (per your spec):

  1. Submit a name + port. Backend calls the GitHub API to create rndexp-art/svc-<name>, scaffolds it from templates/service, and pushes main + production.
  2. In the gateway repo, branch feat/add-<name> off production (production is the safe base — main may carry not-yet-deployed work), add the new repo as a submodule, enable it in config/services.yml, commit, push.
  3. The card below appears with a Merge to production button. Clicking it opens a PR feat/add-<name> → production, merges it (squash), which triggers deploy-gateway.yml; once green, the dashboard fast-forwards main from feat/add-<name> so future PRs see the new submodule too.

Pending merges here will list every open feat/add-* branch found via the GitHub API.
